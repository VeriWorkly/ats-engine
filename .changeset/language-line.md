A resume in a language the engine has no pack for now says so, instead of a lower score with no reason.

- **Breaking:** `report.locale` gains `unsupported`: the language a resume is written in when the policy recognises it (`text.otherLanguages`) and no pack read for it is that language, as an ISO 639 code (`"it"`, `"ja"`), a script the policy names no single language for (`"Cyrillic"`), or `"und"` for an entry of words alone; `null` otherwise. `parsingWarnings` gets the matching line: "This resume looks Italian, which the engine does not read yet: section names, dates and degrees were read as English, and the English writing checks were skipped." Such a resume was already read that way, silently; this line changes no score or field (21,402 runs over the fixtures, the private graded resumes, the review cases and 300 generated resumes, with and without packs, options and postings, were the same apart from it). With the built-in packs attached, only the Italian and Russian test resumes get it; with no pack attached (`check(text)` on `DEFAULT_POLICY`) a German, French or Hindi resume gets it too, since nothing reads those languages then: attach `BUILT_IN_LOCALES` with `withLocales`.
- **Breaking:** the policy's `text.otherLanguages` entries take an optional `id`, an ISO 639 code. The default policy names its eight word lists (es, pt, it, fr, de, nl, pl, sv) and the scripts one language writes (Greek el, Hebrew he, Japanese kana ja, Hangul ko, Thai th, Tamil ta, Telugu te), and checks Japanese kana before Han, so a Japanese resume is named Japanese rather than by the Han script it shares with Chinese. An entry whose `id` is the policy's own language, or "und", is skipped, so a German-language policy that keeps the default list no longer reads German resumes in "und". The default policy's fingerprint changes; its value in this release is in the next entry.
- The CLI prints the line under "Read as", once, with or without a posting; the MCP text answer and the GitHub Action's summary print it too.
